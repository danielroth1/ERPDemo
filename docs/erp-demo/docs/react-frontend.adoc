== The frontend as the user's single entry point

The frontend is a React and TypeScript single-page application built with Vite. From the user's perspective it behaves like one application, but internally it coordinates several backend capabilities exposed through the gateway and service-specific APIs. That distinction is important because the frontend is where the architectural choices of the entire system become visible: GraphQL powers flexible read models, REST is used for straightforward commands, and SignalR updates the UI when background work completes.

The browser is intentionally kept away from internal infrastructure. It never connects directly to PostgreSQL, Kafka, RabbitMQ, or MinIO. Those systems remain behind backend APIs so the application can enforce authorization, validation, workflow rules, and data ownership in one place. That is the safest and most portable pattern for distributed web applications.

			<ApolloProvider client={apolloClient}>

Feature code then chooses the right backend integration style for the job. A typical screen might load a read model through GraphQL, execute a mutation or CRUD action through REST, and listen for background updates through SignalR.

[source,tsx]
----
export function InventoryPage() {
	const [products, setProducts] = useState<ProductSummary[]>([]);

	useEffect(() => {
		void inventoryApiClient.api.v1.products.get().then(response => {
			setProducts(response?.items ?? []);
		});
	}, []);

	return (
		<section>
			<h1>Inventory</h1>
			<ProductTable products={products} />
		</section>
	);
}
----

For real-time experiences such as dashboards, the browser connects to a SignalR hub or GraphQL subscription endpoint after authentication so updates arrive without constant polling.

Representative source: {repo-base}/frontend/src/services/signalr.service.ts#L17[frontend/src/services/signalr.service.ts#L17]

[source,typescript]
----
const connection = new HubConnectionBuilder()
	.withUrl(`${getApiBaseUrl()}/dashboardHub`, {
		accessTokenFactory: () => token,
	})
	.withAutomaticReconnect()
	.build();

await connection.start();
connection.on('lowStockAlert', alert => {
	console.log('Received live alert', alert);
});

== Analysis

[cols="1a,1a",options="header"]
|===
| Advantages | Trade-offs

|
* *One cohesive user experience*: the browser hides the complexity of many backend services behind one application shell.
* *Technology flexibility*: React works well with REST, GraphQL, and real-time channels in the same UI.
* *Fast local loop*: Vite keeps the inner development cycle fast even when the backend is distributed.
|
* *State management needs discipline*: mixing several API styles can become confusing without clear conventions.
* *Authentication and real-time logic add complexity*: token renewal and reconnect behavior must be handled deliberately.
* *Frontend simplicity is partly an illusion*: the browser looks simple because the backend absorbs a lot of architectural complexity.
|===
